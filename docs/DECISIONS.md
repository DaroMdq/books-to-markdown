# Decisions

Numbered so code, tests and later work can cite them. The figures quoted come from the private corpus of 12 technical books this tool was developed against (publisher EPUBs, typeset PDFs and PDF-derived EPUBs); the books themselves are copyrighted and are not in the repository.

**The standing-condition field.** Some entries end with the thing that would reopen them. Write one whenever a decision is right only because of something that happens to be true today: a book that ships a certain way, a dictionary that exists on this machine. The *why* says what was decided; the condition says what would undo it. It is not a required field, and inventing one to fill the slot is worse than leaving it out.

## Output shape

| # | Decision | Why |
|---|---|---|
| N1 | Markdown with YAML front-matter, one file per chapter | A chapter is the unit a retrieval hit should return: big enough to carry an argument, small enough to fit a context window. Markdown survives being read by a human, which is what makes a bad conversion visible at all. JSONL would have hidden every defect this project found. |
| N2 | The front matter is a census, not just provenance | `equations: 148` on a chapter that produced none is the failure mode this project exists to catch, and it is visible without opening the file. Provenance alone would not have caught anything. |
| N3 | Page numbers become `<!-- page N -->` HTML comments | Invisible when rendered, greppable when a retrieval hit needs to cite a printed page. A visible marker would have to be stripped by every downstream consumer; an invisible one costs nothing to ignore. |
| N4 | One CLI, two pipelines, no shared option parser | An EPUB has no page range and a PDF has no spine. A shared parser would have to advertise flags that are ignored on one side, which is how a flag ends up silently doing nothing. |
| N5 | Figures are opt-in behind `--images` | One publisher EPUB stores line charts as full RGB PNG: 2 GB for 611 figures, against 57 MB after palette quantisation. The alt text already carries the meaning for the books that have it, and the images regenerate in about 90 seconds. |
| N6 | Index and table-of-contents documents are dropped as navigation | They are lists of links to content, not content. Kept, the contents page is the longest "chapter" in the book and every retrieval hit lands in it. |

## What is inferred, and what is refused

| # | Decision | Why |
|---|---|---|
| N7 | Chapter boundaries for a flat spine come only from *exact* contents-page matches that move forward through the book | One PDF-derived EPUB has 129 sections and no hierarchy. Fuzzy-matching dot-leader contents text against section headings would have produced chapters, and no way to tell the right ones from the wrong ones. 23 chapters recovered, nothing guessed. **Standing condition:** if a book yields fewer than 5 exact matches the converter keeps one file per section and says so, rather than lowering the bar. |
| N8 | Every PDF threshold is measured off the document, never hard-coded | Two typeset PDFs in the corpus share almost no layout: different body size, different heading convention, different folio position. A constant that works for one is a silent deletion in the other. `Profile.measure` runs before anything is converted. |
| N9 | Running furniture is recurring *text*, not a recurring position | The first version treated any recurring y-height as a header band. One book sets body text from y=44, and the rule silently ate 6,000 words. Furniture is now recognised as a *small string vocabulary* at a given height: one title per chapter, at most. |
| N10 | Furniture removal drops the specific heights furniture occupies, never everything above or below them | Fixing N9 was not enough: "Example 1.1 (Continued)" at y=48 was still taking body text at y=44 with it. A band is the wrong shape for the rule. |
| N11 | Digits are normalised out of the furniture key | "Page 41" and "Page 42" are the same running head. **Standing condition:** a *body* line differing from its neighbours only by a number, set in the top or bottom band of every page, would be dropped. No book in the corpus contains one; `test_a_head_that_differs_only_by_its_page_number_is_still_furniture` records the trade-off. |
| N12 | The outline level used for chapters is the deepest one that still averages ≥ 8 pages per unit | One book puts chapters at level 2 under parts; another puts them at level 1 with 85 sub-sections below. Taking every level in the second gave 53 files averaging 400 words. |
| N13 | Ligature repair is dictionary-checked, and off by default | `profi table` → `profitable` is safe; `skated off ice` → `office` is not. Two guards: the joined form must be a real word, and the two fragments must not both be words already. One book needed 914 repairs; another needed none, and running it there would have been all risk and no gain. |
| N14 | A folio is a bare number outside the *measured* text column, at any height | One book sets its page number beside the text block, not under it, so a footer-band rule found nothing. An earlier attempt used a page-width fraction and caught table numbers instead. |

## Two fixes that went too far, and where they were stopped

| # | Decision | Why |
|---|---|---|
| N15 | Heading parts are concatenated, not joined with a space | Joining split InDesign's per-letter spans into "Ex ecution" and "Tacti c four". **The cost is stated rather than hidden:** a publisher who emits two heading spans with no whitespace between them gets them welded. A `<br/>` is what keeps `CHAPTER 2` and its title apart, and `test_two_spans_separated_by_a_break_are_joined_and_not_run_together` records which side of the trade-off this is on. |
| N16 | A page marker found inside a heading is emitted, not discarded | Stripping it out of the title is right: it must not reach the slug or the filename. Dropping it entirely made the first printed page of every chapter the one page that could not be cited: 28 of them in one book. The marker is held and emitted ahead of the heading. |
| N17 | The whitespace-tidying pass parks code fences behind placeholders | The pass that collapses runs of spaces reached inside fences and flattened 237 C++ listings to one leading space: still fenced, still present, nesting gone. Anything added to that pass must respect it. |

## Completeness

| # | Decision | Why |
|---|---|---|
| N24 | Converting is not finished until `h2m verify` has run | Every defect this project has had produced output that looked right. Structure is cheap to check and proves the shape; only a comparison against the source proves the content. It was added last and immediately found 145 missing tables in the book that had been checked hardest. |
| N25 | The comparison is a stream of letters and digits, with every space and mark of punctuation removed | The converter reflows lines, heals hyphenation across a line break and repairs split ligatures. All three move the spaces and none loses a letter, so a word-level comparison scores the converter's own correct behaviour as loss. |
| N26 | The recovery figure is a band, not a grade | Running heads and folios are removed on purpose, one per page, and the metric counts each as missing. No real book reaches 100%; across the corpus the band is 92–99%. Two secondary signals are read alongside it: paragraph-sized gaps, and characters missing per page. **Standing condition:** the band is twelve books wide. A thirteenth landing outside it is a question, not a verdict. |
| N27 | The source is restricted to what the output says it converted | The index and the contents page are dropped as navigation (N6), and in one book they are 86,000 characters between them. Rolled into one percentage they are indistinguishable from lost book. The kept documents are read back out of each file's own `source_file:` / `pdf_pages:` field, and whatever was skipped is named and measured rather than subtracted. |
| N28 | A figure containing a table is a table, not a picture | At least one publisher wraps every data table in `<figure>`, the element it also uses for a photograph. The picture path rendered the caption, emitted an image reference and returned, discarding the table: 145 tables and 35,779 words of one book, with the caption sitting directly above each hole. |
| N29 | `--fix-ligatures` refuses to run without a system word list | With no dictionary the repair returns the text unchanged and reports zero repairs, which reads exactly like a book that needed none. One book needs 1,394 repairs per 100k words; a silent zero there is a corrupted book nobody questions. |
| N30 | A page that is overwhelmingly rotated is a landscape page, and its rotated lines are content | Rotated text is normally margin furniture (some books set their running heads that way), so every rotated line was dropped. But a table too wide for the page is turned a quarter turn rather than shrunk, and then the rotated text is the whole page. In one 367-page book, 23 pages are landscape tables and none reached the converter: 13 tables gone, caption and all. Measured across the corpus, the two cases do not overlap (a rotated running head is 1–11% of its page, a landscape table 97–100%) and a minimum line count keeps a page holding nothing but a rotated caption out of it. **Standing condition:** only a quarter turn anticlockwise is handled, because it is the only rotation the corpus uses for a table. |
| N31 | The ligature repair reads the first word list that exists, never the union, and every repaired chapter records which one | Unioning is worse than either list: a bigger dictionary makes more fragments valid words on their own and the second guard then declines the join. Measured on one book: `american-english` alone gave 1,108 repairs and 7 residual fragments; unioned with Webster's 2nd, 994 and 11. The deeper problem was reproducibility: output depended on which packages a machine happened to have, and nothing in a converted file said what it had been repaired against. `ligature_dictionary` and `ligatures_repaired` in the front matter close that. |
| N32 | Control characters are scrubbed for classification only, never from the text itself | A glyph the font's ToUnicode map does not cover arrives as a C0 control. One book trails one off every verso folio, and because a backspace is not whitespace, `str.strip()` left it and the bare-number test failed: 117 of 256 pages lost their marker in an exactly alternating pattern, which no reading of the output would show. Scrubbing the *output* would be worse: in other books the same codepoint is a real symbol (a multiplication sign, a vertical bar, both confirmed by rendering the glyph). The substitution is a space rather than nothing, because a folio set inside the running head needs the whitespace between them. |
| N33 | A bare number that steps in lockstep with the page index is a folio, however few pages carry it | A chapter opener suppresses the running head, so the folio drops to the foot, where it appears on too few pages to read as furniture while sitting inside the text column: 67 opener pages across four books lost their marker. What separates a folio from any other number at a fixed height is that it counts along with the pages; a part number printed on 23 pages at the same height never does. Three guards, each measured: four pages minimum, 90% lockstep (the roman-to-arabic jump breaks it once in every real book), and one number per page (a height carrying two is a table row). The band is **held, not taken**: it yields a folio only when nothing else on the page did. |

## How this repo is verified

| # | Decision | Why |
|---|---|---|
| N18 | The suite runs on books it builds itself | Real books are copyrighted and not this repo's to distribute. A synthetic EPUB in a publisher's shape is also a better test document: it says out loud which convention it stands for. **The cost is stated in `tests/conftest.py`:** it proves the convention is handled as understood, not as the book actually ships it. |
| N19 | Real books are a second, separate gate, run outside the repo | A change to `src/h2m/` is not finished when `bin/check` is green: it is re-run against the private corpus and the output diffed against a known-good tree. Every diff must be explained before it is committed; so far every one has been an improvement (recovered page markers, recovered tables). |
| N20 | The mutation table is run, not trusted | Eight rows of the table in `docs/ROADMAP.md` came back NOT CAUGHT the first time they were run; each was a test that looked like coverage and was not. |
| N21 | `bin/check` purges `__pycache__` on every run | CPython validates cached bytecode against mtime in whole seconds plus size. A mutation pass produces exactly the same-size, sub-second edits that defeat that check: a test once passed alone and failed in the full run against a source file that was correct on disk. |
| N22 | The bundled example is checked byte-for-byte | `examples/output/` is evidence in the README. `tests/test_examples.py` rebuilds the sample EPUB and re-converts it, so a committed example the current code no longer produces fails the suite instead of going stale. |
| N23 | Ruff ignores carry their reason inline | `%`-formatting and `l`-for-Line are deliberate. A rule turned off because it was noisy teaches the next reader to turn off the next one. |
